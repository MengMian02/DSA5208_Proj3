## Reproduction

From a clone with `data/covtype.data` present:

```bash
cd supplementary/validation/covertype46
python3 analyze_covertype.py
```

The script reads `../../../../data/covtype.data` via its repository-relative
`ROOT`, reads `centroids.csv`, and writes into this directory:

- `covertype_metrics.json`
- `covertype_clusters.csv`
- `covertype_contingency.csv`
- `table13.csv`
- `figures/covertype_clusters.png` and `.pdf`
- `figures/covertype_contingency.png` and `.pdf`

`analyze_covertype_original.py` is the byte-preserved source of the analysis
methodology; `analyze_covertype.py` changes only path resolution, Table 13/PDF
outputs and no numerical algorithm.

## Report mapping

For the revised Section 15, Table 13 follows `table13.csv`; Figures 16–17
follow the generated PDFs. Figure 16 is a stacked-count composition **within
each cluster** (cluster totals = 581,012). Figure 17 is the contingency matrix
normalized **within each known cover type** (row normalization), so each row
shows where that known type is distributed across clusters. The current v6 report still contains the historical
91-iteration result; the team is updating Section 15 to this 46-iteration
evidence. The two are not merged.

## Reproducibility limitations

- No raw label vector was saved; labels are recomputed from the preserved
  centroids and original dataset.
- The PBS log does not record the compiler, binary hash or source revision.
  Commit `425c420` is the commit that records the artifacts, not proof of the
  exact binary used by the job.
- The historical PBS helper paths are preserved for authenticity; use the
  documented command and the analysis script in this directory for
  regeneration.
- No performance benchmark was rerun. No original artifact was overwritten.

## 91-iteration distinction
